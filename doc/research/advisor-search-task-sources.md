# Where to get realistic Nevis search tasks

**Start with Teresa Riccobuono’s [client meeting prep checklist on Kitces](https://www.kitces.com/blog/client-meeting-prep-checklist-for-financial-advisors/).** Read “Fundamentals,” “Asset Management,” and “Prior To Appointment.” This is a better starting point than a generic “day in the life”: it names what an advisor needs to look up before meeting an existing client, such as beneficiary designations, the investment policy statement, and permission to share information with an accountant or attorney.

**Use the Financial Planning Association’s [2025 Financial Planning Challenge case study](https://www.financialplanningassociation.org/sites/default/files/2025-02/FPC25%20Case%20Study.pdf) to make the synthetic records realistic.** This student exercise describes a hypothetical household and includes a net worth statement, RSU vesting schedules, and life and disability insurance details. It helps you write document contents and plausible near-matches. It is a source of examples, not a ready-made search benchmark: the students are asked to build a plan, not find documents in a CRM.

## Turn a workflow item into a test

Pick a task only if you can name **what the advisor needs to do, what record would let them do it, and what similar record would not**. Stop the test at finding the record; don't ask the search engine to judge whether the client's plan or coverage is adequate. Write the query separately from the expected result, and give the `q`-only API enough information to distinguish the target. Keep dates and client identifiers synthetic. These examples are proposed tests, not queries observed in practice.

| Advisor task | Example query | Acceptable synthetic result | Near-match that should not count |
|---|---|---|---|
| Open a client’s profile to confirm their contact details (Kitces, “Fundamentals”) | `alex.reed@example.com` | Client whose email is `alex.reed@example.com` | Another Alex Reed with a different email |
| Find the agreed investment guidelines before reviewing a portfolio (Kitces, “Asset Management”) | `Reed investment guidelines` | Reed’s current **Investment Policy Statement** | An unsigned or superseded investment policy statement |
| Find who is named to receive a specific IRA at death (Kitces, “Fundamentals”) | `Reed IRA beneficiary` | On-file **Beneficiary Designation** for Reed’s IRA | A life insurance beneficiary designation or an unfilled IRA form |
| Find permission to share client information with the accountant (Kitces, “Prior To Appointment”) | `Reed permission to share with accountant` | Signed, in-force **Authorization to Release Information** covering that accountant | An accountant’s contact card or an unsigned release |
| Find the employer’s disability coverage terms for a client review (Kitces, “Fundamentals”; FPA, “Insurance, Disability”) | `Morales long-term disability coverage` | Morales’s **Employer Benefits Summary** with long-term disability terms | A short-term disability summary for the same client |
| Find when a client’s company shares vest (FPA, “Jamie’s RSU Schedule”) | `Morales when do company shares vest` | Morales’s **Restricted Stock Unit Vesting Schedule** | A brokerage statement listing shares that already vested |

Start by using four of the document tasks in the benchmark, or use three plus the [assignment’s](../assignment.md) `address proof` → `utility bill` case. Use natural query wording in the test, not a copy of the expected title unless the task is a known-document lookup. Then ask one practicing U.S. advisor or client-service associate: “Which of these did you actually need to find recently? What would you call it, and what’s an easy wrong document to open?” Ask for wording and document types, not client data or search logs; replace weak cases rather than assuming this list reflects task frequency.

**Why these sources (FPF Find and Select Sources for a Current Question, F.1):** Kitces supplies existing-client work and the records it depends on; FPA supplies worked examples with realistic document distinctions. I also checked [XYPN’s planning process](https://www.xyplanningnetwork.com/advisor-blog/xypn-financial-planning-process) and [Schwab’s onboarding workflow](https://advisorservices.schwab.com/content/digital-onboarding-on-schwab-advisor-center). They’re useful if the benchmark expands to onboarding but less direct for recurring review work. None of these sources establishes what any particular firm requires or how often advisors search for each record.
